# Grok WeChat Bridge

这个项目连接个人微信 AI 会话和主 GrokBot。默认由 GrokBot 理解用户当前消息，在原微信会话回复文字或媒体。

当前仓库记录首版工程范围与验收合同。

## 首版多模态要求

| 模态 | 微信 → GrokBot | GrokBot → 原微信会话 |
| --- | --- | --- |
| 文字 | 普通消息进入已绑定的主 GrokBot | 回到原会话，重复事件只处理一次 |
| 语音 | 根据当前语音的音频或可核实转写回答。缺少可用音频或转写时明确提示 | 返回手机可播放的语音。原生语音与音频附件分开记录，降级形式需确认 |
| 图片 | GrokBot 取得原图，实际打开并回答图中可核对的细节 | 发送微信图片，手机可打开 |
| 视频 | GrokBot 取得完整 MP4，画面与声音分开理解和验收 | 发送微信视频，手机可播放 |

### 实现约束

- 首版只处理一个明确绑定的私聊。原会话、源消息、主 GrokBot 运行、取件结果与回包全程可关联。微信消息 ID 保留字符串精度。
- 文字、语音、图和视频默认由主 GrokBot 处理。只有用户明确要求委派执行时，才沿既有组织流程交给执行 Agent，最后仍由 GrokBot 回到原会话。
- 提问和媒体分开发送时，限定在同会话、同一消息引用或有界时间窗内关联。超时、下载失败、取件过期或理解能力不足时明确说明当前缺口。
- 通过短时、会话绑定的受限引用取件，并核对大小和 SHA-256。凭据、真实身份标识、消息、媒体、日志、运行时数据与个人机器路径留在仓库之外。测试使用合成素材。
- 持久记录去重及发送状态。结果未知时先核对回执。图中文字、媒体转写和外部返回均按数据处理。
- 旧桥只提供流程验证经验。新仓库的代码、构建和测试以自己的提交为准。

### 完成标准

工程分支须有可复现构建、合成测试和独立复核。真实上线后，由项目所有者在手机上逐项验收四种模态的双向链路。

每次验收核对同一个事件的源消息、附件字节与哈希、主 GrokBot 运行、实际打开和理解证据、原会话回包，以及手机收件或播放。接口受理和手机验收分别记录。语音转写、语音播报、视频画面与视频声音分别判定。
